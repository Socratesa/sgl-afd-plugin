# Hook 启动与兼容契约

`hooks.py` 声明接入点及其业务行为，`compat.py` 集中处理 SGLang HookRegistry 的私有实现。新增接入点在 `SPECS` 中说明目标、Hook 类型、期望参数、层级和原因；业务模块不直接读取 Registry 状态。

## 启动顺序

1. 包入口保持轻量，不导入 torch 或 CUDA。入口函数捕获导入与注册错误。
2. 注册前检查本次需要的全部目标与参数。入口点只排队，保留 SGLang 加载完各插件后统一应用 Hook 的顺序。
3. 应用前检查冲突和目标是否被替换；应用后检查本插件回调的实际归属。上游捕获并记录的单目标安装异常也会被安装确认发现。
4. 启动进程从解析后的参数激活 role/afd 层；成功应用并确认全部必要 Hook 后才导出 `ASAP_*`，供子进程继承。

非空 `ASAP_ROLE` 或命令行中的 `--asap-*` 表示显式请求。显式请求的导入、预检、注册与安装失败必须终止，不能继续生成一个看似正常的原生服务。入口点和统一应用阶段通过 `SystemExit` 避开上游加载器对 `Exception` 的吞掉行为；CLI 激活时异常直接阻止原始参数构造继续执行。

没有启用请求时，插件接入失败只记录警告，保留原生参数和启动行为。添加 ASAP 参数前必须确认完整 base 层，避免只安装了 `add_cli_args`、却没安装 `from_cli_args` 时接受参数后丢弃其含义。上游将配置文件转换成 CLI 参数，因此这条检查也覆盖配置文件启用路径，无须插件另行解析 YAML。

## 安装确认与共存边界

- 检查目标签名、注册记录与实际执行链。REPLACE 的 `__wrapped__` 仍可能指向被绕过的原函数，所以不能靠元数据链确认执行。
- 在统一应用前注册的其他 BEFORE/AFTER 回调可以共存。测试覆盖其他插件先注册与后注册两种顺序。
- 同目标的其他 REPLACE/AROUND，以及替换目标所属父对象的注册会被拒绝；不能证明它们会调用本插件时，不声明兼容。
- 对已经被 Registry 应用过的目标，不支持再首次安装本插件。重复注册和重复应用本插件已有 Hook 不叠加回调。
- 已注册 AFD Hook 的进程不能再用 CLI 切回非 AFD 角色；否则远端专家替换仍会残留。此类配置冲突在导出环境和构造原生参数前报错，需要使用一致配置重新启动。
- 未识别的包装器或 Registry 结构明确报兼容错误。动态替换函数、重载模块或更换 Registry 应用入口不属于支持的运行方式，后续检查会报告可检测的变化。

这是单线程启动期间的接入契约，不提供运行期热安装或全局事务回滚。可选安装失败时移除本插件尚未应用的注册；已经应用的 base 回调通过完整性检查阻止接受无效 ASAP 配置。显式启用失败的进程应退出后重新启动。

## 测试

可以从源码运行 Registry 与入口测试，无须 torch、CUDA 或模型权重：

```bash
ASAP_TEST_SGLANG_SOURCE=/path/to/sglang \
PYTHONPATH=python:tests \
python -B -m unittest test_hook_registry test_hook_activation -v
```

变量指向包含 `python/sglang` 的 SGLang 仓库，也可指向其 `python` 目录。未指定时尝试使用已安装 SGLang 的源码；没有可用源码会跳过，验收时必须确认实际执行且没有跳过。显式指定了无效目录则报错。

测试从选定源码加载真实的 Registry、插件加载器和环境模块，隔离父包导入，并使用合成目标函数。它们验证实际包装与调用、失败传播、加载顺序、重复激活和未启用行为；不能替代完整依赖环境中的目标模块导入与模型验证。

当前接入测试使用历史验收目标 `baa9befa381511cd4d56f83980951e5a45fffc6d` 的上述源码。完整环境还应运行：

```bash
PYTHONPATH=python:tests python -B -m unittest \
  test_cpu.TestHookActivation test_cpu.TestServerArgsFlow test_cpu.TestDocsInSync -v
```

`TestServerArgsFlow` 需要现有测试约定的 DeepSeek-V4 模型配置。必选用例跳过不能计为通过。Hook 接入通过也不表示 MoE 私有接口、模型加载、CUDA IPC 或推理精度通过；这些仍须在对应上游版本、模型和硬件上分别验证。

## 兼容变化

CLI 名称、环境变量和 A/F 通信协议保持不变。以前可能被忽略的显式启用失败现在会终止；存在无法确认调用关系的插件冲突时需要停用冲突插件或调整接入点后重新验证。Registry 内部结构的访问只存在于兼容层，升级 SGLang 时先验证该层，再验证所有业务接入点。
