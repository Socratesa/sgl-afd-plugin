# PR-04：A 侧占位 experts + 权重过滤 + RemoteMoE

A 角色在 AFD 模式下不再持有任何路由专家：模型里每个 MoE 层的 `experts` 换成无权重的占位模块，`DeepseekV2MoE.forward` 换成"gate 与 top-k 留在 A，专家算完由 F 返回"的前向，checkpoint 里的专家张量根本不读。F 服务是 PR-05；本 PR 用一个只回零的 loopback F（`tests/loopback_f.py`，说真实的 A↔F 协议）验证 A 这一侧。

## 怎么启用

`--asap-ffn-ranks E` 是开关。给了它，A 进入 AFD 模式，装上 `afd` 层 hook；不给，专家留在本地，只验证纯 DP 拓扑（M0 的行为），启动日志里有一行警告。AFD 模式还要求 `--asap-num-replicas D`、`--asap-replica-tp 1`（等于 `--dp-size`、`--tp-size`）和 `--disable-cuda-graph`（对 F 的 stream 等待不能被 graph 捕获）。F 必须先起来：A 的第一个占位专家构造时就向 F 发 `describe`，最长等 `ASAP_CONNECT_TIMEOUT_S`（默认 1800 s）。

```bash
CUDA_VISIBLE_DEVICES=2,3 SGLANG_PLUGINS=sgl_asap_plugin python -m sglang.launch_server \
  --model-path $MODEL --dp-size 1 --tp-size 1 --base-gpu-id 0 --disable-cuda-graph \
  --asap-role attn --asap-ffn-ranks 1 --asap-num-replicas 1 --asap-replica-tp 1 \
  --asap-rdv-addr 127.0.0.1:9600 --asap-n-max 8192
```

A 与 F 的进程必须看到同一组 GPU（`CUDA_VISIBLE_DEVICES` 相同），否则 CUDA IPC 无法打开对端内存。

## 四个 hook

| 目标 | 类型 | 作用 |
|---|---|---|
| `sglang.srt.layers.moe.ep_moe.layer.get_moe_impl_class` | REPLACE | 返回 `AfdRemoteExperts`：没有参数，`DeepseekV2MoE.__init__` 读的属性（`should_fuse_routed_scaling_factor_in_topk` 等）照常提供 |
| `sglang.srt.models.deepseek_v2.DeepseekV2MoE.forward` | AROUND | 持有占位专家的层走 AFD 前向，其余层调用原函数 |
| `...weight_utils.buffered_multi_thread_safetensors_weights_iterator` | REPLACE | 按张量名过滤后再读：不读路由专家和 MTP（147 GB 中的绝大部分） |
| `...weight_utils.safetensors_weights_iterator` | REPLACE | 同上，单线程路径 |

`should_fuse_routed_scaling_factor_in_topk` 决定 A 的 TopK 是否把 `routed_scaling_factor` 乘进路由权重，这个值由 F 一侧的量化方法决定（Hopper 上 `Mxfp4FlashinferCutlassMoEMethod` 为 True）。所以占位专家构造时向 F 要它，并拒绝 F 用了 A 的前向没有复现的合并方式的情况。

## 一层 MoE 的前向（`model/afd_forward.py`）

```
gate、top-k      原样用 sglang 的模块，hash 层用 input_ids_global；得到逻辑专家 id 和最终权重
send             把 x、ids、w 排到当前 stream 上发给每个 F rank（只发有效行）
shared expert    和 F 的计算重叠
combine          对每个 F rank 排 stream 等待，把各 rank 的部分和相加（E>1 时用 fp32 累加再舍入一次）
合并             与 stock 的 fused 分支一致：shared.add_(routed, alpha=1 或 routed_scaling_factor)
```
整个过程只入队，主机不等 F。0 个 token 的 rank 不发消息；带 padding 的批只发前 `num_token_non_padded` 行，padding 行的路由结果为零。

## 验收标准

一条命令：`python scripts/pr04_acceptance.py --gpus 2,3`（A 在第 1 张，loopback F 在第 2 张，加载真实 DeepSeek-V4-Flash 权重）。

| ID | 检查 | 通过标准 |
|---|---|---|
| U1 | A 侧单元测试 | ≥ 44 个用例，0 失败，0 跳过 |
| G0 | A rank 在真实权重上启动（4 层，43 层） | `/health` 200 |
| G1 | hook 全部生效 | 启动进程与 scheduler 都是 8/8 |
| G2 | A rank 保留的权重 | 4 层 < 6 GB，43 层 < 14 GB（没有专家张量被分配或读取） |
| G3 | 请求走完每个 MoE 层 | 10、500、3000、6000 token 的请求全部成功 |
| G4 | F 看到全部 MoE 层，没有丢消息 | 层数 = 模型层数，`lost_messages` = 0 |

单元测试（`tests/test_afd_forward.py`，GPU）把真实的 `remote_moe_forward` 接到 loopback F rank 上，用假的 gate/top-k/shared 模块逐位核对：普通层、hash 层、空批、padding 行、不带 shared expert，F 为 1 或 2 个 rank，合并方式为"已乘进 top-k"或"在求和后乘"。`tests/test_afd_pieces.py`（CPU）覆盖张量名选择、过滤迭代器、配置与端点。

## 限制

- 每个副本只支持 `--tp-size 1`。`tp_size > 1` 需要把 token 按 TP 行切开发送、收回后 all-gather，并先对 shared expert 做 all-reduce 再加路由结果；`afd_forward` 里对 `group != 1` 抛 `NotImplementedError`，启动校验也会拒绝。
- 不支持 CUDA graph（A 启动时检查）。
- 只支持 bf16 激活，`hidden`、`topk` 以模型配置为准；`--asap-n-max` 要不小于一次 forward 里的 token 数，超出会报错并指向 `--chunked-prefill-size`。
- F 的量化方法必须是 stock 里 `maybe_fuse_routed_scale_and_shared_add` 走 fused 分支的那几种（MXFP4 flashinfer、Marlin、ExpertPack）。
